# MINIM 本地与官方差异评估

核验日期：2026-11-02，Asia/Shanghai。对象为当前工作区、现存训练检查点，以及本次在线查询的官方代码、数据和论文。此次没有重新训练；模型参数与数据哈希为本次实查，测试成绩取已保存的实际评估产物。

**结论：本地原始数据与官方公开数据完全一致；GATv2 骨干及原始训练目标保留了官方实现。当前工程同时包含硬件适配和非官方修复实验，必须按具体检查点区分。官方论文与公开发布本身也存在模型宽度、数据规模和划分差异，因此目前完成的是公开实现的本地重训与诊断，尚不能称为论文原始结果的严格复现。**

官方代码当前 HEAD 为 `456c60b6fd47941d1e5849db573dbbcb488e3ae7`，与本地基准提交相同。数据当前版本为 `fd1786cb08dc42173905588e7ca015de968c8134`，与下载脚本固定的版本相同。

来源：[官方代码](https://github.com/yyyyhx/MINIM/tree/456c60b6fd47941d1e5849db573dbbcb488e3ae7)、[公开数据](https://huggingface.co/datasets/Chaoyu112358/MINIM-data/tree/fd1786cb08dc42173905588e7ca015de968c8134)、[论文](https://proceedings.mlr.press/v306/yu26bq.html)。

**代码：核心算法仍可对齐，但当前目录已经不是未经修改的官方仓库。**

官方提交共 13 个受版本管理的文件；本地其中 10 个有修改。`evaluate_metrics.py`、`requirements.txt`、Table 2 脚本逐字节未变。新增的 `scripts/`、`tests/`、`reports/` 属于本地工程。

| 本地变化 | 是否改变原始方法 | 本次核验与影响 |
|---|---|---|
| 本地加载 MiniLM、磁盘缓存、流式读图、下载及运行脚本 | 原始路径原则上不变 | 原始特征生成函数仅重命名，AST 一致；主要解决内存与重复编码成本 |
| 将 GATv2 前向拆为 logits 与期望分数，增加可选先验校正 | 关闭校正时不变 | 两种宽度使用相同权重和随机图进行比较，前向最大绝对差均为 0，state_dict 严格兼容 |
| `--task_encoding unique` | 改变任务输入 | 用固定词表的唯一 one-hot 编码替代旧哈希；仅修复版使用，默认仍为 legacy |
| `ci_ce`、`balanced_ce`、`balanced_l1` | 改变训练目标 | CE 和类别平衡均不是论文原始 CI-L1；默认仍为 ci_l1 |
| `--prior_correction` | 改变修复模型的推理分数 | 平衡 CE 修复版使用；原始模型和单因素 CI-CE 未启用 |
| Table/Figure 脚本传递任务词表，增加 CSV 和 TCNP 列 | 原始模型指标公式不变 | 使修复版训练与测试输入编码一致，增加可审查输出 |

`split_rows`、`ci_loss`、`ui_structural_features`、图边构造、文本拼接、MiniLM 特征函数等 20 个原有顶层定义 AST 未变。此结论针对实现本身；不同 batch、数据或损失的训练运行仍会产生不同权重。

公开实现本身用 `goal_id` 哈希到 32 个任务桶，MiniLM 编码节点文本；没有对自由文本任务描述做语义编码。本地原始路径沿用这一实现。公开 34 任务版本已有同树、相同输入而必要性标签不同的碰撞实例；先前确认的四对冲突都涉及额外 `T_` 任务。原来的 27 任务在各域内未发现这种任务桶碰撞，而且 27 任务 CI-L1 仍失败，故不能把碰撞视为全部失败的解释。唯一任务词表也不等于解决了未见自然语言任务泛化。

**模型：结构兼容不代表使用了作者训练好的权重。**

本次重新查询官方 GitHub 文件树、Releases 及作者链接的数据仓库：没有发现 MINIM 成品检查点，Releases 为空。本地五个主要检查点均为本地训练权重，均可严格载入固定官方提交的 GATv2 类；修复版的任务词表和先验校正仍须由本地加载器恢复，单纯加载参数不足以恢复其完整行为。没有运行作者原始权重，也无法比较两者的实际参数值。

| 模型项目 | 官方公开代码 | 官方论文 | 本地情况 |
|---|---|---|---|
| 输入 | 384 维 MiniLM + 128 维 UI | 512 维输入 | 原始与后续主要模型均为 512 维 |
| 骨干 | 三层 GATv2，4 heads | 三层 GATv2，4 heads | 一致 |
| hidden | 默认 496 | 附录 B.2 为 256 | 首轮 496；后续对照及修复版 256 |
| 双评分头 | hidden→128→11，softmax 期望得分 | 256→128→11 | 架构遵循对应宽度 |
| 可训练参数 | 496 配置：1,627,990 | 按公开类实例化 256：595,990 | 本次实际计数；不包含冻结的 MiniLM |
| 优化器、轮次 | AdamW，lr=3e-4，weight decay=1e-5，10 epochs | 相同 | 原始全量及 CI-CE 单因素对照相同；小规模修复为 40 epochs |
| batch | 默认 32 | 32 | 首轮 16；27 任务对照和 CI-CE 原生 32；另有 34 任务 micro-batch 4 累积至 32 的对照 |
| 目标与选模 | CI-L1，alpha=lambda=1，保存末轮 | CI-L1；10 epochs | 原始对照一致；修复路径存在 CE、类别平衡、验证集选模等变化 |

首轮 496 比 256 配置约多 2.73 倍可训练参数。首轮 batch 从 32 减到 16 会改变每轮更新次数和优化轨迹，不能当成严格等价适配；后续原生 batch=32 的 27 任务实验已补上这项控制。

文本编码器是同名官方 `sentence-transformers/all-MiniLM-L6-v2`，本地固定 revision `1110a243fdf4706b3f48f1d95db1a4f5529b4d41`。本次将 90,868,376 字节的 `model.safetensors` 与该 revision 的官方 LFS SHA256 比较，一致：`53aa51172d142c89d9012cce15ae4d6cc0ca6895895114379cacb4fab128d9db`。论文未给出其精确 revision，故只能确认与公开同名模型固定版本一致，不能确认作者当年所用的全部编码器文件及库版本。

**数据：原始公开数据没有本地内容差异，清洗视图不是论文原数据的精确恢复。**

本次从 Hugging Face 固定版本分页获取全部文件元数据，对本地 manifest 逐字节比较，并对所有 5,750 个树文件计算 Git blob SHA1 与官方对象核对：全部一致。集合也一致，没有漏下载、缺失树、坏 JSON 或分数越界。共读取 5,440,118 个节点记录；它们包含各任务和 persona 下的重复页面节点，不是同等数量的独立样本。

| 数据版本 | 基础树 / 任务 / 变体 | train / val / test | 与官方关系 |
|---|---|---|---|
| 论文 | 150 / 27 / 5,403 | 4,741 / 未单列 / 662 | 原始逐样本 split 未在已查公开入口找到 |
| 官方公开版 = 本地 `data/` | 150 / 34 / 5,750 | 本地按官方 split 算法及 seed=0 得 4,637 / 629 / 484 | 数据逐文件哈希完全匹配 |
| 本地 `data_paper_aligned/` | 150 / 27 / 5,400 | 4,356 / 592 / 452 | 仅过滤 350 个 `T_` 变体；仍比论文少 3 条 |
| 修复扩展 `repair_30` | 训练仅 30 棵树、340 变体 | 340 / 185 / 484 | 训练和验证过滤重复 persona；测试使用公开全量 split 的测试部分 |

公开全量域分布为 Gmail 2,950、Reddit 1,300、Shopping 1,500；过滤后为 2,800 / 1,200 / 1,400。清洗视图通过符号链接访问原树文件，本次确认全部 5,400 个文件与 `data/` 对应同一物理文件；没有重写标签。

五个主要运行的 train/val/test 基础树均无交集。完整公开版、27 任务版和单因素 CI-CE 使用相同的 120 / 15 / 15 棵基础树划分。分组隔离可靠，但测试页面和任务分布仍不等于论文 662 个测试变体；不能据本地与论文的分数差直接宣布优于论文。

27 任务原始模型的真实关键节点保留率为 0。表面 3.54% 的 TCNP 来自 16 个没有关键节点的变体默认计 1，不代表保留了任何关键节点。CI-CE 单因素版真实节点微平均保留率为 0.995559，真实交互节点微平均保留率为 0.995475，和表中按变体平均的官方 TCNP 不混用。

已有受控诊断支持：零标签占多数时，原始 L1 信号推动预测下降，softmax 期望分数趋于饱和，Adam 历史状态影响恢复。27 任务原生 batch32 仍失败，排除了“仅因额外阅读任务或仅因 batch 适配”这一解释；保持其余配置只换 CI-CE 则恢复，证明损失替换足以解除本案例的退化。证据不证明作者实际用了 CE，也不证明单一因素解释作者论文与本地的全部分差。

**评估与可复现性的剩余边界。**

- 指标文件与官方逐字节一致。TCNP 将 Abstract 也算作保留；TISL 是 token/风险分数代理，只针对任务无关节点，不是实际泄漏概率。官方 Abstract 代理 `max(6, 0.05*tok)` 对短文本甚至可能高于 Keep。这些是沿用的官方定义，不是本地偷换指标。
- CI-CE 虽然保留率高，其敏感节点识别召回仅约 48.35%，高敏且关键节点的 Abstract 召回约 37.07%。这些成绩不足以证明所有敏感字段得到正确脱敏；也没有真实代理任务成功率实验。
- 正式比较目前只有一个 seed。本地单因素对照的内部可比性强于直接对比论文，但仍不构成多种子统计结论。
- 官方 requirements 没有固定版本。本地环境记录了 PyTorch 2.10.0+cu128、PyG 2.8.1、sentence-transformers 6.2.0；作者精确环境未明，不能声称运行环境一致。库差异只是未控制因素，目前没有证据认定其是失败原因。
- 当前默认评估入口仍指向首轮 `runs/minim/model.pt`，不会自动改用 CI-CE。评估时应显式传入 checkpoint、split、data_root，避免把不同运行混成“当前模型”。
- 通用输出存在来源辨识风险：当前 `results/dataset_validation.json` 记录 5,400 条，实际对应清洗视图，不能用来证明 `data/` 总量只有 5,400；部分训练绘图脚本还复用根目录输出。此次独立核验写入单独目录，未覆盖既有实验结果。
- 缓存键只包含模型类型、模型名称和相对树路径，没有原始文件内容哈希、数据 revision 或 `MINIM_EMBEDDER_PATH`。本次原始数据和编码器均验证匹配，但以后更换数据/编码器而复用同目录缓存可能读入旧特征；应换缓存命名空间或补充键的来源信息。

建议保留 `paper_aligned` 作为原始配方失败对照，使用 `full_ci_ce` 作为明确标注“仅改训练目标”的工作基线。若目标是论文数值的严格复现，优先补齐作者原始 checkpoint、逐样本 split、数据版本和实际训练配置；继续调整本地模型无法替代这些证据。

本次证据目录：[results/local_official_comparison_20261102](../results/local_official_comparison_20261102/)。其中 `dataset_byte_verification.json` 为全量数据校验，`local_verification.json` 为结构、配置、权重哈希和划分核验，`local_vs_official.patch` 为实现差异，`hf_pinned_tree.json` / `hf_embedder_pinned.json` 为上游元数据。`recheck.py` 可用项目 `.venv/bin/python` 在任意工作目录执行，重新核验本地结构及检查点；全量远端数据哈希校验使用另存的固定版上游元数据，结果保存在独立 JSON。
