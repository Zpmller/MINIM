# CE 高分复核：2026-11-05

**确定性复核结论：原始高分可以复算，未发现直接读取测试标签或用预测值自归一化造分的证据；同时确认近重复页面跨集、测试输入重复以及非常强的简单基线。高保留率不足以支持此前对真实任务泛化的乐观解读。**

此次没有修改模型、原始标签、官方指标或旧结果，也没有根据本轮测试重新调参。主要对象为27任务CI-CE检查点；34任务版使用其既存逐节点分数做敏感性分析，未声称重新执行了34任务模型前向。

## 1. 原始结果是否能重新得到

直接从固定官方提交加载GATv2类，严格载入27任务CE权重，对全部452测试变体重新推理。独立按原JSON标签计算：

| 指标 | 本次重算 |
|---|---:|
| TCNP | 0.993766835 |
| TCNP-I | 0.993754247 |
| TISL | 0.037915070 |
| 排除空关键集合后的宏平均TCNP | 0.993538095 |
| 真实关键节点保留 | 17036 / 17112 |
| 真实关键交互节点保留 | 16720 / 16796 |

与既有结果的最大差异小于1e-6；TISL差约6.3e-10。检查点哈希仍为 `29a3d04edd1e0863ecbe71a9b3be5fe92ecf47d3b362bcb390e1d835fc6e9e33`。因此高分并非只来自空分母计满分，也不是仅把旧表格复制为新结果。

## 2. 标签是否泄漏到模型输入

- 数据集提供 sensitivity_score / necessity_score 标签，评估没有从模型输出构造真值。
- 代码中的原始标签与 node_features 分开保存；GAT前向仅接收节点特征和边。
- 全部452条测试缓存标签与原JSON逐项匹配。
- 三域各取一张测试图，节点数99、5104、1431，关闭缓存重新用本地固定MiniLM生成特征。缓存与重算最大差仅 3.61e-07。
- 将同三张图的标签全部改成10，在临时文件中重新生成特征，节点特征及边逐位不变；再将推理对象标签改成10，CPU输出逐位不变。原数据没有改动。

最初用GPU重复前向要求逐位相等的检查触发断言；复查发现未改标签的GPU重复前向也有约1e-6级差异。随后以确定性CPU检查标签依赖，结果为严格相等。两次日志均保留，没有把GPU小数归约噪声当成标签泄漏。

这些结果支持已查路径无直接标签注入，不等于证明项目全部潜在数据来源和全部字段都完全无风险。上游标签属于数据集提供标注，不自动等同于人工实测任务成功。

## 3. ID分组隔离不等于内容真正独立

train/val/test基础树ID无交集，但对150棵基础树进行不依赖标签的可见特征与3跳图邻域匹配，发现4棵测试树、1棵验证树与训练树近重复：

- 测试购物页面：task_125、task_143、task_192、task_230。
- 验证购物页面：task_232。
- 一个匹配训练页面为 task_96；每棵1431节点，其中1430节点的可见文本/角色/深度等签名一致，1427节点的3跳WL邻域签名仍一致；对应匹配节点的标签相同。

近重复标准为0跳和3跳签名多重集交集均覆盖两侧超过99%的节点。先按输入分组，之后才检查标签。WL指纹不是图同构证明；扫描每个基础树的一个代表变体，并不能保证所有任务/persona版本都完全同形。普通文件哈希或保留节点顺序的比较未发现完全相同图，说明先前仅查ID或整图精确哈希不充分。

27任务测试的452变体，按不含标签的原节点JSON和任务ID精确去重后，只有 **113** 种可见输入，来自15棵基础树。重复persona不能视作额外独立泛化场景。

训练集任务/角色/文本键在测试节点中的命中率为 84.95%，在关键节点中为 42.85%。这是给定精确键定义的统计，不应把普通UI公共文本复用全部称作泄漏。

## 4. 不训练神经网络，也可以达到100%关键保留

新增两个只使用训练标签的对照。训练时每树/任务取一个重复persona代表，得到1089张图；预测只使用已知输入，不查看测试标签，不按测试结果调整规则。统一官方阈值1/5。

| 模型或规则 | TCNP | TCNP-I | TISL↓ |
|---|---:|---:|---:|
| 训练集按域＋任务＋角色取平均分 | 1.000000 | 1.000000 | 0.123843 |
| 再加精确文本查表，未知文本退回角色均值 | 1.000000 | 1.000000 | 0.109347 |
| 冻结官方模型载入本地CE权重 | 0.993767 | 0.993754 | 0.037915 |

简单规则也能保留全部关键节点，说明TCNP≈99%本身不是强泛化证据。不过简单规则的泄漏明显高于CE，不能反过来说CE没有价值。角色均值基线的敏感度召回约30.01%，与CE约48.35%也均不充分。

## 5. 排除已发现近重复后，结果如何

这只是既有预测上的事后敏感性分析，没有重新训练，没有构造新的独立测试集，不覆盖所有可能的相似模板。

| 配置 | 原测试TCNP / TCNP-I / TISL | 排除近重复后的TCNP / TCNP-I / TISL |
|---|---|---|
| 27任务CE，1/5 | 0.993767 / 0.993754 / 0.037915 | 0.991714 / 0.991697 / 0.039158 |
| 34任务CE，1/5 | 0.980167 / 0.985172 / 0.075128 | 0.975460 / 0.981749 / 0.077669 |

27任务由452降为340变体，34任务由484降为364变体，两者都剩11棵基础测试树。CE仍有很高保留率，说明近重复页面不是高分的全部解释；简单规则在剔除后也仍100%保留，固定任务与节点标签规则的易学习性同样重要。

## 6. 高TCNP并不代表全部隐私处理正确

27任务CE只识别出约48.35%的高敏节点，高敏且关键节点的Abstract召回约37.07%。TCNP把Keep和Abstract都算作保留；TISL只统计真实必要性≤1的敏感内容，并不覆盖任务所需秘密的脱敏正确性，也没有实际浏览器任务成功率测试。

只有一个seed；测试页面很少、多个persona重复，并且同一测试集已在多轮探索中反复使用。此前用本地与论文的不同测试划分直接判断“效果更好”或把ID不重叠视为充分独立，解释过强，应当收窄。

## 7. 更准确的项目结论

**这些分数是可重新算出的本地离线基准结果；目前证据支持模型学习了这一模板化节点标注任务，尚不足以证明在内容真正独立的新页面、新任务或真实隐私场景上有同等性能。** 原始L1退化与CE解除退化的同条件观察仍成立，但泛化结论需另做严格去重的新划分、多种子及字段级脱敏/代理成功率评估。
